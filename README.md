# Ghostfolio 每日持仓诊断

一个跑在 [Hermes Agent](https://hermes-agent.nousresearch.com/docs) 上的个人**组合状态监控 + 风险诊断**日报。

**标签**：本地数据采集 · 公开量化规则判定 · 免费数据源 · 中文白话报告 · 无自研评分 · 风险优先

---

## 一、这是什么

每天从免费公开数据源采集 9 个持仓标的（6 只美股 ETF + 3 个加密货币）的行情、新闻、宏观和链上数据，
用**公开量化项目的原始规则**得出「规则状态」，再生成一份**中文白话**日报。

设计上最核心的一条分界：

```
公开量化规则  →  描述当前状态（事实层）
ML / 宏观 / 链上 / 基本面  →  只做解释和参考（无任何决策权）
Hermes 主模型  →  只负责翻译与白话点评（不覆盖规则判定）
```

**判定规则全部来自公开项目源码，没有一处阈值是我们自己拍的：**

| 资产类别 | 来源项目 | 使用的规则 |
|---|---|---|
| 美股 / ETF | QuantConnect / Lean | 三个官方 Alpha Model（RSI 状态机 / EMA 交叉 / MACD） |
| 加密货币 | freqtrade | 三个社区策略多数表决（AdxSmas 趋势 / BbandRsi 均值回归 / AwesomeMacd 动量） |

> **v10.0 的身份转换**：报告不再输出「买入 / 卖出」这种操作指令，
> 改为输出**规则状态**（多数偏多 / 多数偏空 / 多数中性 / 无共识 / 固定资产状态）。
> 原因是项目自己的回测已经证明规则层不能作为长期择时依据 ——
> 状态描述是事实，买入建议是承诺，两者不能混。
> 身份：`Trading Signal Generator` → **`Portfolio State Monitor`**。

## 二、⚠️ 请先读这一节：这些规则**跑不赢买入持有**

**这是本项目最重要的前提，比任何代码细节都重要。**

规则本身**如实反映源码定义的当前状态** —— 这是事实层，没有问题。
但把它当作择时策略用在长期持仓上，**回测显示系统性跑输买入持有**。

**完整交易回放（无前视偏差、含手续费+滑点，5 年）：**

| 标的 | 规则年化 | 买入持有 | 超额 |
|---|---|---|---|
| BNB | +15.5% | +12.0% | **+3.5%** ✅ |
| QQQ | +6.9% | +14.4% | −7.6% |
| SCHD | +1.8% | +9.9% | −8.1% |
| ETH | −14.0% | −5.8% | −8.3% |
| VOO | +4.7% | +13.0% | −8.3% |
| SIVR | +12.3% | +21.8% | −9.5% |
| BTC | −1.4% | +10.9% | −12.3% |
| SMH | +10.4% | +33.9% | −23.4% |

**美股/ETF 平均超额 ≈ −10%；加密 ≈ −6%。9 只里只有 BNB 跑赢。**

### 仓位口径敏感性：ETF 12 组全部为负；加密 6 组里只有 1 组为正

**美股/ETF 各期平均超额**

| 口径 | 训练期 2021-2024 | 验证期 2025 | 留出期 2026+ |
|---|---|---|---|
| `long_flat`（卖出/持有都清仓）| −5.7% | −26.9% | −14.5% |
| `long_short`（卖出→做空）| **−11.5%** | **−30.9%** | **−26.5%** |
| `hold_keep`（持有→保持昨日仓位）| **−2.4%** | **−10.3%** | **−20.1%** |
| `scaled`（仓位 = 净票数 / 总票数）| −6.0% | −30.0% | −18.6% |

**加密货币各期平均超额**

| 口径 | 训练期 | 验证期 | 留出期 |
|---|---|---|---|
| `long_flat` | −8.1% | +10.1% | −3.3% |
| `scaled` | −7.5% | −2.9% | **+1.6%** |

> 加密 `scaled` 留出期看似转正，但拆到个股就明白：**这个正数完全由 BNB 一只贡献**
> （BNB +28.4%，同时 BTC −16.0%、ETH −7.4%）。不是「口径救活了策略」，是单只标的的偶然表现。

### 🆕 成本敏感性：零成本下依然大幅跑输

| 成本倍数 | ETF 训练期 | ETF 验证期 | ETF 留出期 |
|---|---|---|---|
| **0×（理想化无成本）** | **−5.2%** | **−26.2%** | **−13.7%** |
| 0.5× | −5.5% | −26.6% | −14.1% |
| 1×（当前假设）| −5.7% | −26.9% | −14.5% |
| 2× | −6.3% | −27.7% | −15.2% |

**这是本项目最有价值的一条诊断结论。**

成本从 0 加到 2 倍，各期超额只恶化约 1~2 个百分点；
而**在零成本、零摩擦的极端假设下，规则依然跑输买入持有 5~26 个百分点**。

→ **交易成本不是主要归因**：即使零成本、零摩擦，规则的长期市场暴露仍明显落后于 Buy & Hold。
→ **问题是规则本身的市场暴露不足 / 方向错误** —— 它把大量时间放在现金上，
   而错过的上涨远多于躲过的下跌。

> ⚠️ **措辞边界**（三方评审后收窄）：本实验排除的是**交易摩擦成本**这个归因，
> **不等于「频繁状态切换本身无害」**。turnover 高除了成本，还会通过
> exposure discontinuity、错过趋势、regime switching 伤害收益 ——
> 这些机制与「手续费」是两回事，本实验未单独分离。

### 结论

1. **做空不是解药** —— 每一期都更差。
2. **HOLD 保持仓位**在训练/验证期收窄缺口，但**留出期反而最差**（典型训练期错觉）。
3. **按票数缩放仓位**对 ETF 无帮助；加密的正数由单只标的贡献。
4. **零成本下仍跑输** → 问题在规则本身。
5. **这条结论已经查得足够深** —— ETF 四种仓位口径 × 三个时段 × 四档成本全部为负；
   加密只有「`scaled` × 留出期」为 **+1.6%**，且完全由 BNB 单只贡献（拆开看 BTC −16.0%、ETH −7.4% 都是负）。
   **没有任何跨资产、跨时期都成立的正面证据。**

> ⚠️ 措辞诚实标注：本项目做的是「**时间段留出检验**」（全样本连续回放 + 超额按段切片统计），
> **不等于**严格的独立样本外 / walk-forward（状态机跨段延续）。本项目规则不含可调参数，故未做 walk-forward。

**已写入硬约束：报告里不得出现「建议买入/卖出」这类操作指令。**

**这个项目真正的价值在别处** —— 集中度超限提醒、风险贡献、状态变化播报、数据质量可见性。

## 四、怎么跑

**环境**：Python 3.13，依赖见 `requirements.txt`（`pandas` / `numpy` / `yfinance` / `lightgbm` / `scikit-learn`，代理场景另需 `PySocks`）。
（`validate_adx_against_talib.py` 额外需要 `ta` 包，仅该脚本用）

**自检与契约测试（不需要任何 API key，不访问网络）：**

```bash
cd scripts

python3 ghostfolio_rules.py --selfcheck        # 判定层
python3 ghostfolio_rule_eval.py --selfcheck    # 回测 + 生产/回测一致性
python3 ghostfolio_market_open.py --selfcheck  # 交易日历
python3 ghostfolio_news.py --selfcheck         # 新闻层
python3 ghostfolio_contract_test.py            # 🆕 数据契约（含变异测试）
```

**回测（四种仓位口径 + 成本敏感性）：**

```bash
cd scripts
python3 ghostfolio_rule_eval.py --split                 # 默认 long_flat
python3 ghostfolio_rule_eval.py --split --short         # long_short
python3 ghostfolio_rule_eval.py --split --keep          # hold_keep
python3 ghostfolio_rule_eval.py --split --scaled        # scaled
python3 ghostfolio_rule_eval.py --split --cost-mult=0   # 成本敏感性 0/0.5/1/2
```

**跑完整日报（需要环境变量，见下）：**

```bash
python3 ghostfolio_collect.py > /tmp/gf.json   # 采集 + 判定
python3 gen_report.py /tmp/gf.json /tmp/gf.md  # 生成中文报告
```

**需要的环境变量**（不设也能跑，对应数据源会降级并记入 `data_quality`）：

```
GHOSTFOLIO_ACCESS_TOKEN   持仓数据（Ghostfolio 匿名 JWT）
GF_CONFIG                 配置文件路径（可选，默认自动查找）
GF_TLS_INSECURE=1         关闭 TLS 校验（不推荐，仅特殊代理环境）
```

## 七、请重点评审的问题

1. **第二节那 24 组实验** —— 证据链认同吗？
   特别是**成本敏感性**：零成本下仍跑输 5~26 个百分点，是否足以排除「成本/turnover」这个归因？
2. **报告改版是否到位** —— 首页已改成风险事件等级、判定已改成「规则状态」、
   「三位投资人」已降级为附录。还有哪些地方读起来仍像交易建议？
3. **风险层的算法** —— `risk_contribution` 用 `w_i(Σw)_i / (w'Σw)`、
   相关性用近 90 日收益。窗口选择、负风险贡献（如 SCHD −0.0055）的处理是否合适？
4. **「小改动引发连锁失效」的形态** —— 目前已踩过四种：
   用产出当健康度分母、元数据塞进他人维护的 `try` 块、自检只覆盖主路径、
   **改完忘了写回文件**。还有哪些地方容易发生？
5. **契约测试的覆盖是否充分** —— fixture 覆盖 9 种场景 + **29 个变异样本**，还缺哪些不变量？
6. **`ghostfolio_collect.py` 要不要拆分？**（本轮明确未做）
   有评审认为它是 God Script、是多个 bug 的根源；
   本轮判断是「先立数据契约，不急着拆文件」—— 拆文件本身不产生正确性收益、纯风险，
   而契约立起来后非法组合根本进不了 JSON。**这个判断对吗？拆分能带来什么契约给不了的东西？**
7. **还有没有漏掉的工程隐患**（数据契约、路径、状态语义这类）？
